# יומן הנדסי

יומן זה מתעד החלטות טכניות ושינויים משמעותיים במערכת לאורך זמן.
כל רשומה כוללת תאריך, תיאור ההחלטה והסיבה לה.

---

## 2024-11-01 — בחירת מסד הנתונים: SQLite

**החלטה:** שימוש ב-SQLite כמסד הנתונים.

**סיבה:** הפרויקט בשלב פיתוח ראשוני. SQLite מגיע מובנה עם Python ו-Django,
אין צורך בהתקנת שרת נפרד, וזה מאפשר להתחיל לפתח מיידית.

**השפעה:** קובץ `db.sqlite3` נוצר בשורש הפרויקט. כל הנתונים שמורים בו.

**הערה לעתיד:** בסביבת ייצור עם עומסים גבוהים יש לעבור ל-PostgreSQL.
השינוי דורש עדכון `DATABASES` ב-`settings.py` בלבד — ללא שינוי קוד.

## 2024-11-10 — הוספת CustomUser במקום User הסטנדרטי

**החלטה:** הרחבת `AbstractUser` ליצירת `CustomUser` עם שדות `role` ו-`team`.

**סיבה:** המערכת דורשת שדות נוספים על המשתמש (תפקיד וצוות) שאינם קיימים
במודל הסטנדרטי של Django. הרחבת `AbstractUser` היא הדרך המומלצת על ידי Django.

**שינוי ב-settings.py:**
```python
AUTH_USER_MODEL = "Django_App.CustomUser"
```

**אזהרה:** שינוי זה חייב להתבצע לפני המיגרציה הראשונה. שינוי לאחר מכן מורכב מאוד.

## 2024-11-15 — מבנה טבלת tasks — הוספת שדה created_by

**החלטה:** הוספת שדה `created_by` למודל `Task`.

**סיבה:** נדרש לדעת מי יצר כל משימה לצורך ביקורת (audit) ובעתיד — הצגת היסטוריה.

**מיגרציה שנוצרה:** `0001_initial.py`

**הערה:** `on_delete=CASCADE` על `created_by` — מחיקת יוצר המשימה תמחק את המשימה.
זו החלטה שניתן לשקול לשנות ל-`SET_NULL` בעתיד.

## 2024-11-20 — הוספת מערכת הרשאות מבוססת תפקיד

**החלטה:** הרשאות מנהל נבדקות ב-View level לפי `team.admin_id == user.id`.

**סיבה:** המערכת פשוטה עם שני תפקידים בלבד (admin/user). שימוש ב-Django Permissions
המלא היה מורכב מדי לצורך זה.

**יישום:**
```python
is_manager = bool(user.team and user.team.admin_id == user.id)
```

**מגבלה:** הבדיקה מתבצעת בכל View בנפרד — אין middleware מרכזי.
